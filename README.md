# Seer中控台Pro

赛尔号多账号中控工具（Python 重构版）。

> 原版为易语言（EPL）实现，现重构为 **Python 3 + PySide6**，保留全部 Win32 自动化能力。
> 公开仓库包含 Python 实现、测试和脱敏示例。原版参考资料和本机工作规范仅在本地保留。

## 功能概览

控制三种游戏客户端（**雷小伊** / **重聚** / **XryM**）完成自动登录、日常任务、巅峰 PVP：

- **账号管理**：16 字段账号数据（兼容旧 15 字段）（`账号文本.txt`，GBK），仓库页统一编辑，勾选同步到运行页
- **批量操控**：日常（雷小伊）/ 巅峰（重聚）批量 运行 / 关闭 / 重启 / 平铺排列
- **单号操控**：运行页账号表格右键菜单，单号 运行 / 关闭 / 重启、复制账号 / 密码
- **定时启动**：日常、巅峰各自独立定时（时 / 分）
- **掉线自检**：周期检测登录状态，自动重启掉线账号
- **客户端管理**：自定义客户端列表（分类：登录器 / 日常 / 巅峰），现行日常 / 现行巅峰单选，批量运行与自检使用其路径；支持版本检测与更新（XM 启动自动更新见 [XryM] xrym启动更新 配置）
- **微信通知**：pushplus 推送（登录超时、临期账号、全部完成）

## 界面三页

| 页面 | 内容 |
|------|------|
| **运行页** | 活动账号表格（只读）+ 游戏客户端列表（三列三大行：分类合并居中 / 名称 / 版本）+ 日常 / 巅峰控制面板（现行软件标签、运行关闭、重启排列、定时自检、时分设置）+ 日志输出 |
| **仓库页** | 全部账号表格（可编辑）+ 客户端路径编辑 + 「保存运行」同步勾选账号到运行页 |
| **配置页** | 客户端管理（名称 / 路径 / 属性 / 现行日常 / 现行巅峰，增删改排序）+ 运行选项 + 辅助（打开账号文本、窗口置顶、不休眠） |

## 技术栈

- **语言 / GUI**：Python 3.13 / PySide6（Qt 6）
- **Win32 自动化**：pywin32 + ctypes（窗口查找、UIA 控件操作、SendInput 模拟点击）
- **进程管理**：subprocess + psutil
- **定时任务**：APScheduler
- **配置解析**：configparser（GBK 编码）

## 快速开始

首次使用先在 PowerShell 中复制示例（文件保持 GBK 编码）：

```powershell
Copy-Item -LiteralPath ctrl.example.ini -Destination ctrl.ini
Copy-Item -LiteralPath 账号文本.example.txt -Destination 账号文本.txt
```

在配置页填写客户端路径；通知 token 按需填写。示例账号默认不选中且日常／巅峰开关均关闭，填写真实账号后再启用。

```bash
# 安装依赖（推荐 uv 或 pip）
uv pip install PySide6 pywin32 psutil apscheduler
# 或
pip install PySide6 pywin32 psutil apscheduler

# 启动（需管理员权限：游戏客户端 requireAdministrator）
python seer_console/main.py
```

## 数据文件

| 文件 | 编码 | 说明 |
|------|------|------|
| `ctrl.ini` | **GBK** | 窗口控件 ID / 坐标（物理像素）、客户端路径、[客户端列表] 节（现行日常/巅峰标记）、定时设置 |
| `账号文本.txt` | **GBK** | 账号数据，管道符分隔 16 字段/行（兼容旧 15 字段）：选中、账号名、米米号、密码、状态、日常/巅峰开关与到期、标注、平台、蓝晶币、紫晶币、刻印等 |

> 修改配置时务必保持 GBK 编码，Python 侧读写均已显式指定 `encoding='gbk'`。

## 关键约定

- **DPI**：Qt 6 默认 Per-Monitor V2，**不要**手动调用 `SetProcessDPIAware()`；引擎内 Win32 坐标一律为物理像素
- **编码**：所有 GBK 文件读写显式指定编码；代码内中文注释
- **UI 线程不阻塞**：Win32 操作在子线程执行，主线程只更新 UI
- **进程清理**：关闭/重启前 `Process.kill()` + `wait()` 确保彻底销毁
- **失焦清选**：四个表格均实现「点击表格外清除选中高亮」（`FocusClearTable`，Qt 6 的 QSS `:!focus` 规则不生效）

## 状态

- 核心业务主流程已跑通：账号加载 / 批量运行 / 日常登录 / 巅峰流程 / 兑换 / 自检框架
- **XM 启动更新**已实现：启动后检测客户端内嵌更新组件页（实测控件：110=本地下载 160=继续使用该版本 130=进度条 140=下载状态）。运行页「日常控制」组框内「自动更新」勾选框（定时启动正上方，仅现行日常软件为 XM 时可用）→ 写回 `[XryM] xrym启动更新`（真/假）分流——假=点「继续使用该版本」直接登录（模式1）；真=自动下载（等 100%+信息弹窗→点确定→旧进程自动退出）→ 按目录最新文件定位新 exe 并写回配置 → 重启新版本继续登录流程（模式2）。批量与单号启动均按勾选分流，仅自检重启不开放更新。批量中首账号更新后，后续账号在锁内复用新版本路径（不再重复下载）；批量关闭后未启动账号直接跳过
- **XM 版本号识别**：XM 作者版本号习惯与其他软件不同（X.X.XX 末段两位数 = 两个子级，如 2.5.21 = 2.5.2.1，新出的 2.5.3 大于旧版 2.5.21），比较函数 `compare_xrym_version` 仅用于 XM（2.5.32 与 2.5.4 可正确排序），通用 `compare_version` 不受影响；下载中断的残件（<1MB）自动过滤
- **XM 更新组件常驻**：实测 2.5.3 起启动页常驻更新组件（id=110「本地下载」按钮永远存在，即使已是最新版本），引擎以 id=170 版本文本对比判定是否有真更新（当前版本==最新版本=无更新直接登录；版本信息为空=网络波动，按 XM 温馨提示点「继续使用该版本」降级运行，不再误点下载卡 600 秒）；手动「更新」按钮与启动版本检查均用 XM 规则，文件无变化提示「无更新」
- **XM 自检 UID 匹配**：实测登录前/登录中用户信息卡显示临时账号（UID=3.1415926、名称=小赛尔），登录后刷新有数秒延迟。登录流程与自检复查先做窗口 UID（id=280）与米米号匹配（最长 10 秒），匹配通过才取昵称（id=290，UID 匹配为准，昵称不做字符串过滤——用户昵称真叫「小赛尔」也照常采用）；匹配失败 → 账号名为空 → 自检进入重启流程，杜绝把临时账号误判为登录成功
- 待完善：狂野模式与巅峰批量兑换的自动化实测

## 本机配置版本和提交检查

真实配置留在项目根目录，用独立的本机 Git 版本库保存快照；默认版本库位于同级 `SEER-private-config/`，不设置远端。

```powershell
python tools/config_history.py save --message "调整日常任务设置"
python tools/config_history.py history
python tools/config_history.py restore --commit <版本号>
# 关闭中控台后显式恢复，先自动保存当前版本
python tools/config_history.py restore --commit <版本号> --apply
```

公开仓库首次克隆后安装本地检查：

```powershell
python tools/repo_guard.py install
python tools/repo_guard.py check
```

完整流程与目录约定见 [维护工具说明](tools/README.md)。
